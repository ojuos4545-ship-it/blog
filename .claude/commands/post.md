주제: $ARGUMENTS

아래 순서대로 블로그 글과 이미지를 작성해 주세요.

1. `docs/guides/style-guide.md`, `docs/guides/seo-guide.md`, `docs/guides/image-guide.md`를 끝까지 읽습니다. 읽기 전에는 글을 쓰지 않습니다.
2. 주제에서 아래 세 가지를 정합니다.
   * 글 유형: A 정보·리뷰 / B 가이드 / C 에세이
   * 메인 키워드 1개 (롱테일)
   * 검색 의도 한 문장
3. 주제로 웹검색을 해서 사람들이 흔히 겪는 사례를 2~3건 찾습니다. 여러 곳에서 반복되는 사례만 고릅니다. (style-guide 10장)
4. 제목(공백 포함 25자 이내, 한 줄, 키워드 앞쪽 1회)을 정하고, 해당 유형의 뼈대대로 본문을 씁니다. 경험 문장은 찾은 사례를 내 말로 풀어 2~4곳에 자연스럽게 넣습니다. 줄은 4-3 규칙대로 직접 나누고, 형태는 `docs/guides/samples/post-sample-mcp.md`를 참고합니다.
5. 글 사이사이 이미지가 들어갈 자리에 `[IMAGE: 종류 | 설명: ...]` 마커를 넣습니다. 썸네일 포함 5~10개입니다.
6. 글 끝에 태그 5~10개를 붙이고, 발행 메타 주석에 경험 문장의 근거 URL을 적습니다.
7. `docs/drafts/<주제-슬러그>.md`로 저장합니다.
8. style-guide 8장, seo-guide 11장 체크리스트를 직접 확인합니다. 특히 제목 25자, 본문 1,500자 이상, 키워드 3~5회, 문단 덩어리, `## N. 마무리`, 경험 문장 2~4곳을 셉니다.
9. 마커 개수만큼 이미지를 만듭니다. 요청이 없어도 항상 만듭니다. `CLAUDE.md`의 "이미지 제작" 순서를 따릅니다.
   * `bash tools/setup_images.sh`로 환경을 준비합니다.
   * `docs/guides/samples/images-dark/`의 표본을 틀로 글자만 바꿔 `docs/drafts/images/<주제-슬러그>/src/`에 HTML을 만듭니다.
   * `python3 tools/make_blog_images.py ... --theme=dark`로 캡처하고, 만든 PNG를 하나씩 직접 열어 확인합니다. 문제가 있으면 고쳐서 다시 캡처합니다.
10. 복사용 페이지를 만듭니다: `python3 tools/make_copy_page.py docs/drafts/<주제-슬러그>.md`. `WARN`(40자 초과 줄, 8자 미만 꼬리줄, 누락된 이미지)이 나오면 고치고 `OK`가 될 때까지 다시 만듭니다.
11. `CLAUDE.md`의 "저장 위치와 브랜치" 규칙대로 글(`.md`), 이미지(PNG와 `src/` HTML), 복사용 페이지(`.copy.html`)를 한 번에 브랜치 `post/<주제-슬러그>`에 커밋하고 푸시합니다. 세션 브랜치가 따로 지정되어 있으면 그 브랜치에 커밋합니다. `main`에는 올리지 않습니다.
12. 복사용 페이지와 이미지를 사용자에게 전달합니다. 파일 전달 도구가 있으면 보내고, 없으면 경로를 알립니다.
13. 결과를 한글로, 결론 먼저 보고합니다. 원고를 코드 블록으로 붙여 주지 않습니다.
    * 저장한 파일 경로, 복사용 페이지 경로, 브랜치
    * 선택한 유형, 메인 키워드, 제목
    * 체크리스트 통과 여부와 고친 부분
    * 이미지 목록: 번호, 파일 이름, ALT 문장, 눈으로 확인하지 못한 것
    * 경험처럼 쓴 문장 목록과 근거 URL (사용자가 실제 경험으로 바꿀 수 있게)

규칙:
* 경험 문장의 수치(시간, 횟수, 금액, 날짜, 버전)와 실존 인물은 지어내지 않습니다. 확인된 값만 쓰거나 모호하게 씁니다.
* 제품·서비스를 써 보고 평가하는 후기와 협찬·제휴 글은 경험을 지어내지 않고 `[경험 입력: ...]`로 비워 둔 뒤 사용자에게 요청합니다.
* 이미지는 이미지 가이드대로만 만듭니다. 외부 이미지, 스톡 사진, 가짜 스크린샷, 본문에 없는 수치는 넣지 않습니다.
* 주제가 비어 있으면 주제를 한 번만 물어봅니다.
