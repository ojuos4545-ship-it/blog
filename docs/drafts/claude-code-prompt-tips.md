# 클로드 코드 요청 잘 쓰는 법 3단계

> 💡 **한 줄 요약:** 클로드 코드 요청 잘 쓰는 법은 구체적으로 쓰고,
> 확인할 기준을 주고, 흐름이 틀어지면 바로 잡는 3단계입니다.

[IMAGE: 썸네일 | 설명: 클로드 코드 요청 잘 쓰는 법 3단계 대표 이미지]

"분명히 시켰는데 엉뚱한 결과가 나와요"
하시는 분들을 위해 준비했습니다.
결론부터 말씀드리면, **클로드 코드 요청 잘 쓰는 법**은
파일과 증상, 완료된 모습을 먼저 알려 주고,
확인할 기준을 함께 주는 것입니다.

요청(프롬프트)이 조금만 달라져도 결과는 꽤 달라집니다.
오늘 이 글 하나만 끝까지 읽으시면
고쳐 달라고 다시 말하는 횟수를 확 줄이실 수 있습니다.
내용은 [Claude Code 공식 모범 사례 문서](https://code.claude.com/docs/en/best-practices)를
기준으로 정리했습니다.

---

## 🛠️ 시작하기 전에 알아둘 것들

* **준비물:** 클로드 코드 설치, 작업할 프로젝트
* **소요 시간:** 요청 하나 고쳐 쓰는 데 금방입니다
* **난이도:** 초급, 대화만 할 줄 알면 충분합니다

공식 문서에 따르면 클로드는 코드를 읽고
파일 구조와 관례를 스스로 찾아냅니다.
대신 회의에서 정한 결정이나 한 사람만 아는 배포 절차처럼
코드에 없는 정보는 알 수가 없죠.
그래서 좋은 요청은 클로드가 볼 수 없는 것을 알려 주는 요청입니다.

저도 "버그 고쳐 줘"처럼 짧게 맡겼다가
생각지 못한 파일까지 바뀐 적이 있어요.
막연한 요청이 엉뚱한 수정으로 이어지는 경우가 꽤 많더라고요.

## Step 1. 클로드 코드 요청은 얼마나 구체적이어야 할까?

처음 쓸 때 가장 많이 놓치는 부분은 완료된 모습입니다.
어떤 파일인지, 어떤 증상인지,
무엇이 되면 끝인지를 먼저 적어 주세요.
두 가지 방법 중 원하는 쪽이 있다면 그것도 미리 말해야 합니다.

공식 문서의 예시를 우리말로 옮기면 아래와 같습니다.

| 이렇게 말하기보다 👎 | 이렇게 말해 보세요 👍 |
| :--- | :--- |
| 로그인 버그 고쳐 줘 | 세션이 만료된 뒤 로그인이 실패한다는 제보가 있어. src/auth/의 토큰 갱신 부분을 보고, 문제를 재현하는 실패 테스트를 먼저 쓴 다음 고쳐 줘 |
| 달력 위젯 추가해 줘 | HotDogWidget.php의 패턴을 따라 월을 고르고 연도를 넘길 수 있는 달력 위젯을 만들어 줘. 새 라이브러리는 쓰지 마 |

[IMAGE: 비교표 | 설명: 클로드 코드 요청에서 막연한 요청과 구체적인 요청의 차이 비교]

이미 가진 자료가 있다면 말로 설명하지 말고 그대로 건네세요.
파일은 `@` 뒤에 경로를 적으면 내용이 함께 들어가고,
화면 디자인이나 오류는 스크린샷을 붙여 넣으면 됩니다.

> 📌 **전문가 Tip:** 클로드는 요청을 보수적으로 읽어서
> 조건을 만족하는 가장 작은 것을 만드는 편입니다.
> 빈 화면, 오류 처리까지 원한다면 그 범위를 직접 적어 주세요.

## Step 2. 클로드가 스스로 확인할 기준은 어떻게 줄까?

기본이 끝났다면 이제 확인할 기준을 붙여 볼 차례입니다.
클로드는 일이 끝나 보이면 멈추는데,
통과와 실패를 알려 주는 검사가 없으면
"끝나 보인다"는 것만으로 판단할 수밖에 없습니다.

그럴듯해 보이는데 막상 돌려 보면
빠진 부분이 있는 결과를 받는 경우가 많더라고요.
검사가 있으면 클로드가 직접 돌려 보고,
깨진 곳을 고친 뒤 다시 확인합니다.

* 테스트 파일
* 빌드 결과(종료 코드)
* 린터
* 결과를 기준 파일과 비교하는 스크립트

요청 끝에 한 줄만 붙여도 됩니다.

```
작업이 끝나면 auth 테스트를 돌리고, 통과할 때까지 계속해 줘
```

[IMAGE: 포인트카드 | 설명: 클로드 코드에 줄 수 있는 확인 기준 테스트, 빌드, 린터와 요청 예시]

"테스트 다 통과했어요"라는 말만으로는 알 수 있는 게 적습니다.
실행한 명령과 그 출력을 함께 보여 달라고 하면
결과를 다시 돌려 보지 않아도 바로 확인할 수 있습니다.

---

## Step 3. 결과가 엇나가면 어떻게 다시 잡을까?

공식 문서는 처음 1분을 지켜보다가
방향이 틀어지면 바로 멈추라고 권합니다.
흐름을 잡는 방법은 세 가지만 알면 충분합니다.

1. `Esc`: 작업을 바로 멈춥니다. (그때까지 한 일은 남습니다)
2. `/rewind`: 코드와 대화를 이전 요청 시점으로 되돌립니다.
3. `/clear`: 대화를 비우고 새로 시작합니다.

같은 부분을 몇 번이고 고쳐 달라고 하다가
오히려 더 꼬이는 일도 흔하다고 해요.
같은 수정을 두 번 했는데도 틀렸다면 세 번째로 고치기보다
`/clear` 후 배운 점을 담아 새 요청을 쓰는 편이 낫습니다.

[IMAGE: 포인트카드 | 설명: 결과가 엇나갈 때 쓰는 Esc, /rewind, /clear 세 가지와 두 번 실패 규칙]

하지만 중요한 건 처음부터 원하는 것을 정리하는 것이겠죠.
무엇을 원하는지 아직 모르겠다면
클로드에게 먼저 질문해 달라고 요청해 보세요.
답을 하다 보면 요청에 들어갈 내용이 자연스럽게 정리됩니다.
