결론부터 말씀드리면, 클로드 코드 요청 잘 쓰는 법은

확인할 기준을 함께 주는 것입니다.

오늘 이 글 하나만 끝까지 읽으시면
고쳐 달라고 다시 말하는 횟수를 확 줄이실 수 있습니다.

• 준비물: 클로드 코드 설치, 작업할 프로젝트
• 소요 시간: 요청 하나 고쳐 쓰는 데 금방입니다
• 난이도: 초급, 대화만 할 줄 알면 충분합니다

공식 문서에 따르면 클로드는 코드를 읽고

대신 회의에서 정한 결정이나 한 사람만 아는 배포 절차처럼
코드에 없는 정보는 알 수가 없죠.
그래서 좋은 요청은 클로드가 볼 수 없는 것을 알려 주는 요청입니다.

저도 "버그 고쳐 줘"처럼 짧게 맡겼다가

Step 2. 클로드가 스스로 확인할 기준은 어떻게 줄까?

기본이 끝났다면 이제 확인할 기준을 붙여 볼 차례입니다.
클로드는 일이 끝나 보이면 멈추는데,
통과와 실패를 알려 주는 검사가 없으면
"끝나 보인다"는 것만으로 판단할 수밖에 없습니다.

그럴듯해 보이는데 막상 돌려 보면
빠진 부분이 있는 결과를 받는 경우가 많더라고요.
검사가 있으면 클로드가 직접 돌려 보고,
깨진 곳을 고친 뒤 다시 확인합니다.

• 테스트 파일
• 빌드 결과(종료 코드)
• 린터
• 결과를 기준 파일과 비교하는 스크립트

Step 3. 결과가 엇나가면 어떻게 다시 잡을까?

공식 문서는 처음 1분을 지켜보다가
방향이 틀어지면 바로 멈추라고 권합니다.
흐름을 잡는 방법은 세 가지만 알면 충분합니다.

1. Esc: 작업을 바로 멈춥니다. (그때까지 한 일은 남습니다)
2. /rewind: 코드와 대화를 이전 요청 시점으로 되돌립니다.
3. /clear: 대화를 비우고 새로 시작합니다.

같은 부분을 몇 번이고 고쳐 달라고 하다가
오히려 더 꼬이는 일도 흔하다고 해요.
같은 수정을 두 번 했는데도 틀렸다면 세 번째로 고치기보다
/clear 후 배운 점을 담아 새 요청을 쓰는 편이 낫습니다.
