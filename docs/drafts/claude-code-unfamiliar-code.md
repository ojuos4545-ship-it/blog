# 클로드 코드로 낯선 코드 파악하는 3단계

> 💡 **한 줄 요약:** 클로드 코드로 낯선 코드 파악은
> 전체 지도 받기, 기능 하나 따라가기,
> 근거 확인하고 기록하기의 3단계면 충분합니다.

[IMAGE: 썸네일 | 설명: 클로드 코드로 낯선 코드 파악하는 3단계 대표 이미지]

"새 프로젝트에 들어왔는데 파일이 너무 많아서
어디부터 열어 봐야 할지 모르겠어요" 하시는 분들을 위해 준비했습니다.
결론부터 말씀드리면, **클로드 코드로 낯선 코드 파악**은
전체 구조를 넓게 묻고, 기능 하나를 끝까지 따라간 뒤,
설명의 근거를 확인해 기록으로 남기면 끝납니다.

저도 문서 하나 없는 프로젝트를 넘겨받았을 때
어디부터 봐야 할지 몰라 파일만 이리저리 열어 봤어요.
같은 이유로 며칠씩 코드 읽기에만 매달리는 분이 꽤 많더라고요.

오늘 이 글 하나만 끝까지 읽으시면 처음 보는 저장소도
순서대로 질문하며 혼자 파악하실 수 있습니다.
질문 예시와 기능 설명은 [Claude Code 공식 문서](https://code.claude.com/docs/en/common-workflows)를
2026년 10월 29일에 확인해 정리했습니다.

---

## 🛠️ 시작하기 전에 준비할 것들

* **준비물:** 클로드 코드 설치, 파악할 프로젝트 폴더
* **권장 설정:** 읽기만 하는 Plan 모드
* **난이도:** 초급, 터미널에서 폴더를 옮길 줄 알면 충분합니다

코드를 파악하는 동안에는 Plan 모드를 켜 두시길 권합니다.
Plan 모드에서는 클로드가 파일을 읽고 계획만 내놓을 뿐,
내가 승인하기 전까지는 아무것도 고치지 않거든요.

```bash
claude --permission-mode plan
```

이미 대화를 시작했다면 `Shift+Tab`을 몇 번 눌러
상태 표시줄에 `⏸ plan mode on`이 보이게 하면 됩니다.
전체 흐름은 아래 그림처럼 세 단계로 나뉩니다.

[IMAGE: 다이어그램 | 설명: 클로드 코드로 낯선 코드를 파악하는 지도 받기, 기능 따라가기, 확인과 기록 3단계 흐름]

## Step 1. 낯선 코드의 전체 구조는 어떻게 물어볼까?

처음 할 일은 프로젝트 맨 위 폴더로 가서
클로드 코드를 실행하는 것입니다.
공식 문서가 안내하는 첫 단계도 바로 이것인데요,
중간 폴더가 아니라 맨 위에서 시작해야 전체를 보고 답해 줍니다.

```bash
cd 프로젝트-폴더
claude
```

첫 질문은 넓게 던집니다.
공식 문서도 넓은 질문으로 시작해
특정 영역으로 좁혀 가라고 안내하는데요.
아래 순서대로 차근차근 따라와 주세요.

1. 전체 개요를 묻습니다.
2. 구조와 설계 방식을 묻습니다.
3. 핵심 데이터와 프로젝트 용어를 묻습니다.

```
이 코드베이스 전체 구조를 설명해줘
여기서 쓰는 주요 설계 패턴을 알려줘
핵심 데이터 모델은 뭐야?
이 프로젝트에서만 쓰는 용어를 표로 정리해줘
```

(이때 주의할 점은 한 번에 다 묻지 않는 것입니다.
답을 하나씩 읽으면서 모르는 단어가 나오면
그 단어를 다음 질문으로 이어 가는 편이 이해가 빠릅니다.)

[IMAGE: 포인트카드 | 설명: 클로드 코드 Step 1 전체 구조를 넓게 묻는 질문 순서와 예시]

> 📌 **전문가 Tip:** 코딩 규칙도 함께 물어보세요.
> "이 프로젝트의 이름 짓기와 폴더 규칙을 알려줘"처럼 물으면
> 나중에 코드를 고칠 때 기존 방식과 어긋날 일이 줄어듭니다.

## Step 2. 기능 하나는 어떻게 따라갈까?

기본이 끝났다면 이제 기능 하나를 골라 끝까지 따라가 볼 차례입니다.
전체 그림만 봐서는 실제로 코드가 어떻게 움직이는지
잘 와닿지 않기 때문이죠.

로그인처럼 내가 맡을 일과 가까운 기능을 고른 뒤,
찾기, 연결 관계, 실행 흐름 순서로 묻습니다.

```
사용자 로그인을 처리하는 파일들을 찾아줘
이 파일들이 서로 어떻게 연결되는지 설명해줘
로그인 과정을 화면부터 데이터베이스까지 따라가 줘
```

처음엔 "이메일 검사하는 코드 찾아줘"처럼 막연하게 물었다가
여기저기 뒤지느라 답이 늦어지는 경우가 많더라고요.
폴더 이름이나 프로젝트에서 쓰는 용어를 함께 적으면
찾는 범위가 좁아져서 답도 빨라집니다.

[IMAGE: 포인트카드 | 설명: 클로드 코드 Step 2 기능 하나를 찾기, 연결, 흐름 순서로 따라가는 질문]

### 파일을 직접 짚어 줄 수도 있을까?

이미 볼 파일을 안다면 `@` 뒤에 경로를 적어 주세요.
파일 내용이 대화에 바로 들어가서
클로드가 찾아 읽는 과정을 건너뜁니다.

```
@src/utils/auth.js 의 로직을 설명해줘
```

폴더를 짚으면 파일 내용이 아니라 파일 목록이 들어갑니다.
그리고 넓은 범위를 뒤지는 검색은 클로드가 알아서
읽기 전용 Explore 에이전트에게 맡기는데요.
직접 맡기고 싶다면 "서브에이전트로 조사해줘"라고 말하면 됩니다.

| 방식 | 장점 👍 | 주의할 점 👎 |
| :--- | :--- | :--- |
| **그냥 질문** | 위치를 몰라도 됨 | 막연하면 오래 뒤짐 |
| **@ 파일 짚기** | 바로 그 파일을 읽음 | 경로를 알아야 함 |
| **서브에이전트** | 긴 검색 결과가 대화에 안 쌓임 | 사용량이 더 듦 |

[IMAGE: 비교표 | 설명: 클로드 코드로 낯선 코드를 찾을 때 그냥 질문, @ 파일 짚기, 서브에이전트 비교]

## Step 3. 클로드 코드의 설명은 어떻게 확인할까?

하지만 중요한 건 설명을 듣는 것이 아니라
**그 설명이 실제 코드와 맞는지 확인하는 것**이겠죠.
클로드가 직접 읽지 않은 부분까지 그럴듯하게 이어 붙여
확신에 찬 말투로 설명했다는 사례가 꽤 많이 올라와 있습니다.

저도 설명만 믿고 넘어갔다가 실제 파일을 열어 보고서야
내용이 다르다는 걸 알고 다시 찾아본 적이 있어요.
그래서 지금은 중요한 설명마다 근거를 꼭 묻습니다.

1. 설명의 근거가 된 파일과 함수 이름을 묻습니다.
2. 짐작한 부분과 코드에서 확인한 부분을 나눠 달라고 합니다.
3. 테스트가 있다면 직접 실행해서 동작을 확인하게 합니다.

```
방금 설명에서 코드로 확인한 것과 짐작한 것을 나눠서,
근거가 된 파일 경로와 함께 알려줘
```

[IMAGE: 포인트카드 | 설명: 클로드 코드 Step 3 설명의 근거 확인과 /init으로 CLAUDE.md 남기기]

### 파악한 내용은 어디에 남길까?

확인이 끝난 내용은 `CLAUDE.md`에 남겨 두면 좋습니다.
`/init`을 입력하면 코드베이스를 바탕으로 첫 버전을 만들어 주고,
이 파일은 다음 세션부터 자동으로 읽힙니다.

다만 클로드가 코드에서 스스로 알아낼 수 있는 구조 설명은 지우고,
코드에 없는 정보만 남기는 것이 공식 권장입니다.
배포 절차나 테스트 실행 명령처럼 코드만 봐서는 모르는 것들이죠.
분량은 200줄 아래로 유지하라고 안내합니다.

다음 날 이어서 파악하고 싶다면 `claude --continue`로
같은 폴더의 가장 최근 대화를 다시 열면 됩니다.
