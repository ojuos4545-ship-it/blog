# 클로드 에이전트 뜻, 서브에이전트와 차이

> 💡 **한 줄 요약:** 클로드 에이전트 뜻은 도구를 써서
> 일을 끝까지 해내는 AI이고, 서브에이전트는 그 에이전트가
> 일부 작업을 떼어 맡기는 별도 도우미입니다.

[IMAGE: 썸네일 | 설명: 클로드 에이전트 뜻과 서브에이전트 차이 대표 이미지]

안녕하세요, 여러분!
요즘 클로드를 쓰다 보면 "에이전트"라는 말이 정말 자주 보이는데요.
챗봇과 무엇이 다른지, 서브에이전트는 또 무엇인지
막상 설명하려면 헷갈리셨죠?

저도 처음엔 에이전트가 똑똑한 챗봇을 부르는 새 이름인 줄 알았어요.
회사와 서비스마다 같은 말을 조금씩 다르게 쓰다 보니
헷갈린다는 분이 꽤 많더라고요.

바쁘신 분들을 위해 결론부터 짚어볼게요.
**클로드 에이전트 뜻**은 목표를 받으면 스스로 도구를 고르고,
결과를 확인하며 일을 끝까지 이어 가는 AI입니다.
서브에이전트는 이 에이전트가 조사나 검토 같은 일을 떼어
따로 맡기는 보조 에이전트이고, 일을 마치면 요약만 돌려줍니다.

이 글을 끝까지 읽으시면 두 개념을 구분하고,
서브에이전트를 언제 쓰면 좋은지까지 판단하실 수 있습니다.
내용은 [Anthropic 공식 글](https://www.anthropic.com/engineering/building-effective-agents)과
[Claude Code 공식 문서](https://code.claude.com/docs/en/sub-agents)를
2026년 10월 29일에 확인해 정리했습니다.

## 1. 클로드 에이전트 뜻 - 챗봇과 무엇이 다를까?

Anthropic은 에이전트를 AI 모델이 스스로 작업 순서와
도구 사용을 정하는 시스템이라고 설명합니다.
정해진 순서대로만 움직이는 워크플로와 달리,
에이전트는 도구를 쓰고 그 결과를 보며
다음 행동을 고르는 과정을 반복하죠.

클로드 코드가 대표적인 예입니다.
공식 문서는 클로드 코드가 맥락 파악, 행동, 결과 확인의
세 단계를 오가며 일한다고 설명하는데요.
"실패하는 테스트를 고쳐줘"라고 하면 테스트를 돌려 오류를 읽고,
관련 파일을 찾아 고친 뒤, 테스트를 다시 돌려 확인하는 식입니다.

[IMAGE: 다이어그램 | 설명: 클로드 에이전트 작업 루프: 맥락 파악, 행동, 결과 확인 반복]

이렇게 일을 해낼 수 있는 건 도구 덕분입니다.
공식 문서도 도구가 없으면 클로드는 글로 답만 할 수 있고,
도구가 있어야 파일을 읽고 고치고 명령을 실행할 수 있다고 설명합니다.
챗봇과 에이전트의 차이를 표로 정리하면 아래와 같습니다.

| 구분 | 챗봇 | 에이전트 |
| :--- | :--- | :--- |
| **하는 일** | 질문에 답하기 | 목표를 받아 일을 끝내기 |
| **도구** | 주로 글로만 답함 | 파일, 명령, 웹 검색 등 |
| **진행 방식** | 한 번 묻고 한 번 답함 | 행동하고 결과를 보며 반복 |
| **사람의 역할** | 매번 다음 질문하기 | 중간에 방향 잡아 주기 |

> 📌 **전문가 Tip:** 모든 일에 에이전트가 필요한 건 아닙니다.
> Anthropic도 가장 단순한 방법부터 쓰고,
> 꼭 필요할 때만 복잡도를 높이라고 권합니다.
> 에이전트는 시간과 비용을 더 쓰는 대신 결과를 높이는 방식이거든요.

## 2. 서브에이전트는 메인 에이전트와 무엇이 다를까?

서브에이전트는 특정 종류의 일을 맡는 전문 도우미입니다.
메인 에이전트가 설명에 맞는 일을 만나면 서브에이전트에게 넘기고,
서브에이전트는 자기만의 컨텍스트에서 따로 일한 뒤 결과를 돌려주죠.

여기서 컨텍스트는 AI가 한 번에 보고 기억하는
대화와 자료의 범위를 말합니다.
서브에이전트가 파일 수십 개를 읽어도 메인 대화에는 요약만 돌아오니,
메인 대화의 컨텍스트가 덜 차는 것이 가장 큰 장점입니다.

[IMAGE: 다이어그램 | 설명: 클로드 서브에이전트에게 일을 맡기고 요약을 돌려받는 흐름]

| 구분 | 메인 에이전트 | 서브에이전트 |
| :--- | :--- | :--- |
| **대화 기록** | 지금까지 나눈 대화 전부 | 맡은 일만 받고 새로 시작 |
| **컨텍스트** | 내 대화창과 함께 씀 | 자기 컨텍스트를 따로 씀 |
| **결과** | 과정까지 모두 보임 | 마지막 요약만 돌아옴 |
| **도구·모델** | 세션 설정을 따름 | 따로 정할 수 있음 |

[IMAGE: 비교표 | 설명: 클로드 메인 에이전트와 서브에이전트 차이: 대화 기록, 컨텍스트, 결과, 설정]

저도 처음엔 앞에서 나눈 대화를 서브에이전트도 다 아는 줄 알았어요.
실제로는 맡긴 작업 설명만 받고 새로 시작하기 때문에,
파일 위치나 조건을 빠뜨리면 중요한 내용이 빠진 채
일하게 된다는 후기가 꽤 많더라고요.

그래서 서브에이전트에게 일을 맡길 때는
파일 경로, 지켜야 할 조건, 원하는 결과 형식을 함께 적어 주는 편이 좋습니다.
참고로 서브에이전트는 메인 대화에 결과를 보고할 뿐,
서브에이전트끼리 서로 대화하지는 못합니다.

클로드 코드에는 처음부터 들어 있는 서브에이전트도 있습니다.
따로 만들지 않아도 클로드가 상황에 맞게 꺼내 쓰죠.

* **Explore:** 코드를 빠르게 찾고 분석하는 읽기 전용 도우미
* **Plan:** 계획 모드에서 고치기 전에 자료를 조사하는 도우미
* **general-purpose:** 조사와 수정이 함께 필요한 여러 단계 작업 담당

[IMAGE: 포인트카드 | 설명: 클로드 코드 기본 서브에이전트 Explore, Plan, general-purpose 정리]

이름이 비슷해서 헷갈리는 기능도 두 가지 짚고 넘어갈게요.

* **스킬:** 저장해 둔 부탁을 메인 대화 안에서 그대로 실행
* **에이전트 팀:** 여러 세션이 함께 일하는 구조, 서브에이전트보다 무거움

## 3. 서브에이전트는 언제 쓰면 좋을까? - 장단점 정리

그렇다면 서브에이전트는 언제 쓰는 게 좋을까요?
Anthropic 블로그는 파일 열 개 이상을 건드리거나
서로 상관없는 작업이 세 개 이상일 때 위임을 고려해 보라고 합니다.
읽을 파일이 많은 조사나 여러 파일에 같은 변경을 하는 일이 잘 맞죠.

반대로 앞 단계 결과가 다음 단계에 필요한 일이나
같은 파일을 동시에 고치는 일은 메인 대화에서 하는 편이 낫습니다.
질문 하나로 끝나는 작은 일도 맡기는 수고가 더 클 수 있고요.

| 구분 | 장점 👍 | 단점 👎 |
| :--- | :--- | :--- |
| **컨텍스트** | 메인 대화가 덜 참 | 맡길 때 설명을 다시 써야 함 |
| **비용** | 가벼운 모델로 돌릴 수 있음 | 자기 토큰을 따로 써서 총사용량이 늘 수 있음 |
| **작업** | 서로 상관없는 일을 나눠 처리 | 이어지는 단계, 같은 파일 수정엔 안 맞음 |
| **보고** | 결과만 깔끔하게 받음 | 서브에이전트끼리는 대화 못 함 |

[IMAGE: 비교표 | 설명: 클로드 서브에이전트를 쓰면 좋을 때와 피할 때 비교]

서브에이전트가 편하다고 여러 개를 한꺼번에 돌렸다가
사용량이 생각보다 빨리 줄었다는 후기도 자주 보이더라고요.
공식 문서도 서브에이전트의 요청은 메인 대화와
같은 사용 한도에서 차감된다고 안내합니다.

### 나만의 서브에이전트는 어떻게 만들까?

기본이 이해됐다면 이제 나만의 서브에이전트를 만들어 볼 차례입니다.
가장 빠른 방법은 클로드에게 원하는 서브에이전트를 설명하고
어디에 저장할지 말해 주는 것인데요.
직접 만들 때는 프로젝트의 `.claude/agents/` 폴더에
마크다운 파일을 하나 두면 됩니다.

```markdown
---
name: code-reviewer
description: 코드 품질과 보안을 검토한다. 코드를 고친 뒤 바로 사용
tools: Read, Glob, Grep
model: sonnet
---

너는 코드 리뷰어다. 호출되면 바뀐 코드를 읽고
품질과 보안 문제를 구체적으로 짚어 줘.
```

`name`과 `description`만 꼭 필요하고, 나머지는 고를 수 있습니다.
`tools`로 쓸 수 있는 도구를 줄이고, `model`로 가벼운 모델을 지정하면
비용도 아낄 수 있죠.
모든 프로젝트에서 쓰고 싶다면 `~/.claude/agents/`에 저장하면 됩니다.

클로드는 `description`을 보고 언제 맡길지 정합니다.
그래서 설명이 막연하면 잘 불리지 않으니,
"코드를 고친 뒤 바로 사용"처럼 쓰는 상황을 구체적으로 적어 주세요.
꼭 그 서브에이전트를 쓰고 싶다면 대화창에 `@`를 입력해 골라 부르면 됩니다.

[IMAGE: 포인트카드 | 설명: 클로드 서브에이전트 만드는 법: 파일 위치, name과 description, @로 부르기]

하지만 중요한 건 서브에이전트를 많이 만드는 것이 아니라
**꼭 맡길 일만** 골라 맡기는 것이겠죠.
Anthropic 블로그도 전문 서브에이전트가 너무 많으면
자동으로 맡기는 판단이 오히려 덜 정확해진다고 말합니다.
