# 클로드 코드 되돌리기 사용법 3단계

> 💡 **한 줄 요약:** 클로드 코드 되돌리기 사용법은 체크포인트를 이해하고,
> `/rewind`로 돌리고, 못 돌리는 것을 아는 3단계입니다.

[IMAGE: 썸네일 | 설명: 클로드 코드 되돌리기 사용법 3단계 대표 이미지]

"클로드가 고친 코드가 더 망가졌는데 원래대로 돌릴 수 있을까요?"
하시는 분들을 위해 준비했습니다.
결론부터 말씀드리면, **클로드 코드 되돌리기 사용법**은
`/rewind`를 입력하거나 빈 입력창에서 `Esc`를 두 번 눌러
원하는 요청 시점으로 돌아가는 것입니다.

클로드 코드는 요청을 보낼 때마다 코드 상태를 자동으로 저장해 둡니다.
오늘 이 글 하나만 끝까지 읽으시면
망친 수정도 겁내지 않고 되돌리실 수 있습니다.
내용은 [Claude Code 공식 체크포인트 문서](https://code.claude.com/docs/en/checkpointing)를
기준으로 정리했습니다.

---

## 🛠️ 시작하기 전에 알아둘 것들

* **준비물:** 클로드 코드 설치, 진행 중인 대화
* **소요 시간:** 메뉴 하나만 익히면 금방입니다
* **난이도:** 초급, 키 두 번이면 충분합니다

저도 결과가 마음에 안 들어 처음으로 돌리고 싶었는데
방법을 몰라 하나하나 다시 고친 적이 있어요.
이 기능이 있는 줄 모르는 분이 생각보다 많더라고요.

되돌리기는 체크포인트라는 저장 지점을 기준으로 움직입니다.
요청을 보내면 체크포인트가 생기고,
나중에 그 시점을 골라 코드나 대화를 되돌리는 방식이죠.

[IMAGE: 다이어그램 | 설명: 요청을 보낼 때마다 체크포인트가 저장되고 /rewind로 시점을 골라 되돌리는 흐름]

---

## Step 1. 클로드 코드 체크포인트는 언제 만들어질까?

처음 알아둘 점은 따로 저장할 필요가 없다는 것입니다.
새 작업을 시작하는 요청을 보낼 때마다
그 직전의 코드 상태가 체크포인트로 자동 저장됩니다.

* **개수:** 한 세션에서 최근 100개까지 파일 상태를 보관합니다
* **다시 열기:** 대화와 함께 저장돼서 세션을 다시 열어도 됩니다
* **보존 기간:** 기본값은 마지막 저장 뒤 약 30일입니다

보존 기간이 지나 저장본이 지워진 시점을 고르면
`No files were restored`라는 문구와 함께 실패할 수 있습니다.
더 오래 보관하려면 `cleanupPeriodDays` 설정을 늘리면 됩니다.

[IMAGE: 포인트카드 | 설명: 클로드 코드 체크포인트가 만들어지는 시점과 보관 개수, 보존 기간]

## Step 2. /rewind로 어떻게 되돌릴까?

기본이 끝났다면 이제 실제로 되돌려 볼 차례입니다.
`/rewind`를 입력하거나 입력창이 비어 있을 때 `Esc`를 두 번 누르면
지금까지 보낸 요청 목록이 나옵니다.
되돌아갈 요청을 고른 뒤 아래 중 하나를 선택하세요.

| 선택지 | 코드 | 대화 |
| :--- | :--- | :--- |
| **Restore code and conversation** | 되돌림 | 되돌림 |
| **Restore conversation** | 그대로 | 되돌림 |
| **Restore code** | 되돌림 | 그대로 |

[IMAGE: 비교표 | 설명: /rewind 메뉴의 세 가지 선택지가 코드와 대화를 각각 되돌리는지 비교]

메뉴에서 선택지를 잘못 골라
코드까지 되돌려 버렸다는 이야기도 꽤 있더라고요.
고르기 전에 이름에 code가 들어 있는지 한 번 더 확인하세요.

입력창에 글자가 있을 때 `Esc`를 두 번 누르면
메뉴 대신 입력한 글자가 지워집니다.
지워진 글자는 기록에 남으니 `↑` 키로 다시 불러오면 됩니다.

> 📌 **전문가 Tip:** 메뉴의 Summarize from here를 고르면
> 그 시점 뒤의 대화를 요약해서 공간을 비울 수 있습니다.
> 파일은 바뀌지 않으니 긴 디버깅 뒤에 써 보세요.

---

## Step 3. 되돌리기로 돌아오지 않는 것은 무엇일까?

하지만 중요한 건 되돌리기의 한계를 아는 것이겠죠.
체크포인트는 클로드가 파일 편집 도구로 고친 내용을 기준으로 움직입니다.
그래서 아래 경우는 되돌리기로 돌아오지 않습니다.

* Bash 명령으로만 바뀐 파일
* 대부분의 서브에이전트가 고친 파일
* 클로드 코드 밖이나 다른 세션에서 고친 파일
* 데이터베이스, API처럼 바깥 시스템에 한 작업

Bash 명령으로 지운 파일이 되돌리기로 돌아오지 않아
당황하는 경우가 많더라고요.
이런 파일은 git 같은 버전 관리로 되살려야 합니다.

[IMAGE: 포인트카드 | 설명: 클로드 코드 되돌리기로 복구되지 않는 Bash 명령, 서브에이전트, 바깥 수정, 외부 시스템]

> 📌 **전문가 Tip:** 공식 문서도 체크포인트는
> 세션 안에서 빠르게 되돌리는 용도이고 git을 대신하지 않는다고 말합니다.
> 큰 작업 전에는 커밋을 하나 남겨 두세요.

`Esc` 두 번과 세 가지 선택지만 기억하셔도
