1. 대화의 기본 용어 5가지는 무엇일까?

클로드 코드를 켜면 가장 먼저 만나는 말들입니다.
이 다섯 가지만 알아도 화면에 나오는 안내가
훨씬 덜 낯설게 느껴지실 거예요.

용어뜻 한 줄
에이전트스스로 파일을 읽고 명령을 실행하며 일하는 AI
프롬프트내가 클로드에게 보내는 요청 문장
세션한 폴더에서 이어지는 대화 한 묶음
컨텍스트 창클로드가 지금 참고하는 작업 기억 공간
토큰AI가 글을 잘게 나눠 처리하는 단위

클로드 코드가 에이전트라고 불리는 이유는 도구를 쓰기 때문입니다.
채팅형 AI는 답을 글로만 주지만,
클로드 코드는 파일을 읽고 고치고 명령까지 실행하죠.
공식 문서는 이 과정을 맥락 수집, 작업 실행, 결과 확인을
되풀이하는 에이전틱 루프라고 부릅니다.

【사진 02】

세션은 지금 폴더에 묶인 대화 하나입니다.
새 세션은 이전 대화를 모르는 빈 컨텍스트 창에서 시작하고,
/clear를 입력하면 새 세션이 열립니다.
이전 세션은 지워지지 않아서 /resume으로 다시 불러올 수 있어요.

컨텍스트 창에는 대화 내용, 읽은 파일, 명령 결과,
CLAUDE.md가 함께 담깁니다.
이 공간을 재는 단위가 토큰인데요.
토큰은 단어나 글자 조각 단위라서
같은 글도 모델과 언어에 따라 개수가 달라집니다.
지금 무엇이 공간을 차지하는지는 /context로 확인할 수 있습니다.

2. 작업을 조절하는 용어 4가지는 무엇일까?

기본 용어가 익숙해졌다면 이제 작업 흐름을 다루는 말을
알아볼 차례입니다.
이 네 가지는 실수를 줄이고 되돌리는 데 직접 쓰입니다.

용어뜻 한 줄
명령/로 시작하는 단축 지시 (예: /clear, /model)
권한 모드클로드가 묻지 않고 해도 되는 범위
체크포인트파일을 고치기 전에 남기는 되돌림 지점
압축컨텍스트 창이 차면 대화를 요약해 비우는 일

명령은 흔히 슬래시 명령이라고 부르던 것입니다.
요즘 공식 문서는 '슬래시'를 빼고 그냥 명령(command)이라 부르는데요.
/clear, /model, /compact 같은 기본 명령이 세션을 조절하고,
직접 만드는 명령은 스킬로 만드는 방식을 권장합니다.

권한 모드는 Shift+Tab을 누를 때마다 차례로 바뀝니다.
대표적인 모드는 아래 네 가지입니다.

• 수동(Manual): 수정과 명령 실행 전에 매번 묻습니다
• 편집 허용(Accept edits): 파일 수정은 묻지 않습니다
• 플랜(Plan): 계획만 제안하고 소스 파일은 안 고칩니다
• 자동(Auto): 별도 분류 모델이 위험한 동작만 막습니다

체크포인트는 클로드가 파일을 고치기 전에 남기는 사진 같은 것입니다.
Esc를 두 번 누르거나 /rewind로 이전 상태로 돌아갈 수 있어요.
다만 파일 변경만 되돌리기 때문에 데이터베이스나 배포처럼
외부에 남은 작업은 되돌리지 못합니다.

【사진 04】

압축(컴팩션)은 컨텍스트 창이 가득 차 갈 때
대화를 자동으로 요약하는 기능입니다.
저도 긴 작업 중에 처음 정해 둔 규칙을 클로드가 잊은 듯해서
당황한 적이 있어요.
대화로만 전한 지시가 요약 과정에서 빠진 경우였는데,
같은 일을 겪는 분이 꽤 많더라고요.

📌 전문가 Tip: 오래 지켜야 할 규칙은 대화 대신 CLAUDE.md에 적어 두세요.
공식 문서에 따르면 프로젝트 루트의 CLAUDE.md는
압축이 끝난 뒤 디스크에서 다시 읽어 옵니다.
직접 압축할 때는 /compact 뒤에 남길 내용을 덧붙이면 됩니다.

3. 기능을 넓히는 용어 6가지는 무엇일까?

여기부터는 클로드 코드를 내 작업에 맞게 늘려 쓰는 말들입니다.
처음부터 다 설정할 필요는 없고,
뜻만 알아 두셨다가 필요할 때 하나씩 더하면 됩니다.

용어뜻 한 줄
CLAUDE.md매 세션 시작 때 읽는 프로젝트 규칙 메모
스킬필요할 때 꺼내 쓰는 작업 설명서
서브에이전트따로 일하고 요약만 돌려주는 도우미 AI
MCP외부 서비스와 연결하는 공개 표준
훅정해진 순간마다 자동으로 실행되는 처리
플러그인스킬, 훅, 서브에이전트, MCP를 묶은 설치 꾸러미

CLAUDE.md는 내가 직접 쓰는 메모이고,
클로드가 스스로 적어 두는 메모는 자동 메모리라고 부릅니다.
공식 문서는 CLAUDE.md를 200줄 이하로 짧게 유지하라고 권하죠.

스킬은 /이름으로 직접 부를 수도 있고,
클로드가 작업에 맞다고 판단하면 스스로 불러오기도 합니다.
서브에이전트는 자기만의 컨텍스트 창에서 일하기 때문에
파일을 많이 읽는 조사를 맡겨도 메인 대화가 덜 어지러워집니다.

MCP는 노션, 슬랙, 데이터베이스 같은 외부 서비스를
클로드 코드에 연결하는 방식이고,
훅은 파일을 고친 직후처럼 정해진 순간마다
클로드의 판단 없이 항상 실행됩니다.
플러그인은 이런 설정을 다른 저장소에서도 쓰거나
남에게 나눠 줄 때 한 번에 설치하게 해 주는 꾸러미입니다.

4. 헷갈리는 클로드 코드 용어는 어떻게 구분할까?

가장 많이 묻는 건 스킬, 서브에이전트, 명령의 차이입니다.
저도 셋 다 무언가를 맡기는 기능처럼 보여서
한동안 섞어 썼는데요.
커뮤니티에서도 같은 질문이 자주 올라오더라고요.

언제 불러오는지를 기준으로 보면 차이가 선명해집니다.

용어언제 불러오나잘 맞는 일
CLAUDE.md매 세션 시작 때 자동항상 지킬 규칙, 빌드 명령
스킬필요할 때 (/이름 또는 클로드 판단)반복 절차, 참고 자료
서브에이전트일을 맡길 때 (별도 컨텍스트)파일을 많이 읽는 조사, 병렬 작업
훅정해진 이벤트마다 자동수정 후 검사, 위험한 명령 차단
【사진 06】

명령과 스킬은 사실상 하나로 합쳐지는 중입니다.
.claude/commands/deploy.md와 .claude/skills/deploy/SKILL.md는
둘 다 /deploy를 만들고 똑같이 동작합니다.
차이는 스킬은 클로드가 상황을 보고 스스로 불러올 수도 있다는 점이죠.

하지만 중요한 건 용어를 모두 외우는 것이 아니라
지금 필요한 것 하나를 고르는 것이겠죠.
공식 문서도 같은 실수를 두 번 하면 CLAUDE.md에,
같은 요청을 반복하면 스킬로 옮기라고 안내합니다.

💡 한 줄 구분: 규칙은 CLAUDE.md, 절차는 스킬,
맡길 일은 서브에이전트, 반드시 할 일은 훅입니다.
