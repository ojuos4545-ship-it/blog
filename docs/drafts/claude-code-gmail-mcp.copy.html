【사진 02】

🛠️ 시작하기 전에 준비할 것들

• 준비물: claude.ai 계정, 클로드 코드, 구글 계정
• 소요 시간: 인증까지 금방 끝납니다
• 난이도: 초급, 로그인만 해 보셨다면 충분합니다

여기서 한 가지만 먼저 확인하세요.
클로드 코드를 claude.ai 구독 계정으로
로그인해서 쓰고 있어야 합니다.
공식 문서에 따르면 API 키나 클라우드 제공업체로 쓰는 상태에서는
claude.ai 커넥터가 불러와지지 않습니다.

팀이나 엔터프라이즈 요금제라면
커넥터는 관리자만 추가할 수 있어요.

Step 1. 지메일 커넥터는 어떻게 허용할까?

시작은 터미널이 아니라 브라우저입니다.
claude.ai/customize/connectors에서 서버를 추가하고,
필요한 인증도 그 자리에서 끝냅니다.

아래 순서대로 차근차근 따라와 주세요.

1. claude.ai에 로그인합니다. (클로드 코드와 같은 계정으로)
2. claude.ai/customize/connectors로 이동합니다.
3. 목록에서 Gmail을 찾아 연결을 시작합니다.
4. 구글 로그인 화면에서 접근을 허용합니다.

구글 인증 단계에서 접근 차단 화면이 뜬다는
보고도 있더라고요.
redirect_uri_mismatch라는 오류 이름으로 올라온 사례가 있고,
해당 건은 보고된 날 해결 처리된 것으로 표시돼 있었습니다.
같은 화면이 반복된다면 공식 저장소 이슈에서 오류 이름을 검색해 보세요.

📌 전문가 Tip: 지메일 커넥터는 메일 검색과

묻는다고 안내돼 있으니,
처음 쓸 때 승인 화면을 꼼꼼히 읽어 보세요.

Step 2. /mcp에서 연결 상태는 어떻게 확인할까?

기본이 끝났다면 이제 클로드 코드에서 확인할 차례입니다.
클로드 코드를 실행하고 대화창에 /mcp를 입력하면
claude.ai에서 온 서버에는 표시가 붙어 목록에 나옵니다.

Gmail이 안 보인다면 목록 맨 아래의
Show unused connectors 줄을 펼쳐 보세요.
공식 문서에 따르면 쓰지 않은 커넥터는 그 안에 접혀 있을 수 있습니다.

지메일만 목록에 안 보일 때는 어떻게 할까?

여기서 막히는 분이 꽤 많더라고요.
claude.ai 설정에는 연결됨으로 떠 있는데
클로드 코드 목록에는 지메일만 빠져 있는 경우입니다.
캘린더와 드라이브는 보이는데
지메일만 없다는 글도 여럿 올라와 있었어요.

그럴 때는 아래 순서로 확인해 보세요.

1. /status로 지금 로그인 방식을 봅니다.
2. API 키 로그인이면 /login으로 바꿉니다.
3. claude.ai에서 연결을 끊고 다시 연결합니다.
4. 클로드 코드를 껐다가 다시 실행합니다.

2번에서 바꿀 때는 claude.ai 계정을 선택하면 됩니다.
다만 연결을 끊었다 다시 이어도 안 풀렸다는 글이 있더라고요.
이런 경우는 보고된 버그일 수 있으니
공식 저장소 이슈에서 같은 증상이 있는지 찾아보시는 편이 빠릅니다.

Step 3. 지메일에는 처음에 무엇을 시켜 볼까?

연결이 확인됐다면 이제 실제로 시켜 볼 차례입니다.
처음에는 읽기 중심의 가벼운 요청이 좋아요.
아래처럼 말로 부탁해 보세요.

최근 일주일 안에 온 메일 중 답장이 필요한 것만 골라서 제목과 보낸 사람을 알려줘

요청은 읽기, 초안, 발송 순서로 넓혀 가는 것을 권합니다.
단계마다 확인할 점이 다르기 때문입니다.

단계요청 예시확인할 점
1. 읽기메일 검색, 요약엉뚱한 메일이 섞이지 않았는지
2. 초안답장 초안 작성보내기 전에 내용을 직접 읽기
3. 발송메일 보내기승인 화면의 받는 사람과 본문
【사진 05】

하지만 중요한 건 편리함이 아니라
메일 내용을 어디까지 믿을지이겠죠.
메일은 바깥 사람이 쓴 글이라서,
외부 내용을 가져오는 서버는
프롬프트 인젝션(숨겨진 지시문으로 AI를 속이는 공격)
위험에 노출될 수 있다는 공식 문서의 경고가 그대로 적용됩니다.

📌 전문가 Tip: 특정 프로젝트에서 쓰고 싶지 않다면
/mcp에서 지메일 커넥터를 끌 수 있습니다.
전부 끄려면 아래처럼 실행하세요.
ENABLE_CLAUDEAI_MCP_SERVERS=false claude
