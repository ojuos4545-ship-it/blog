【사진 01】

"분명 얼마 안 썼는데 한도가 벌써 찼대요"
하시는 분들을 위해 준비했습니다.
결론부터 말씀드리면, 클로드 코드 토큰 아끼는 방법은
작업이 바뀔 때 대화를 비우고, 모델을 용도에 맞게 고르고,
파일은 붙여 넣지 않고 경로로 알려 주는 것입니다.

토큰은 AI가 글을 읽고 쓰는 양을 세는 단위로,
많이 쓸수록 사용 한도가 빨리 줄어듭니다.
오늘 이 글 하나만 끝까지 읽으시면
한도를 아끼는 습관 5가지를 바로 적용하실 수 있습니다.
내용은 Claude Code 공식 문서와
공식 도움말을
2026년 11월 5일에 확인해 정리했습니다.

🛠️ 시작하기 전에 - 토큰은 어디서 새어 나갈까?

• 준비물: 클로드 코드, 평소 쓰던 프로젝트 하나
• 소요 시간: 습관 하나당 금방 끝납니다
• 난이도: 초급, 명령어 몇 개만 알면 충분합니다

클로드 코드는 질문할 때마다 이전 대화 전체를 다시 함께 보냅니다.
여기에 프로젝트 규칙 메모인 CLAUDE.md와 읽은 파일,
새 질문까지 더해지는데요.
그중 가장 빨리 커지는 것이 이전 대화라서
긴 대화일수록 한 번 물을 때마다 더 무거워집니다.

【사진 02】

Step 1. 대화는 언제 비워야 할까?

처음에 가장 많이 하는 실수는
한 대화창에서 다른 작업까지 이어서 시키는 것입니다.
저도 비슷하게 쓰다가
한도가 생각보다 빨리 줄어 있어서 놀란 적이 있어요.
이전 작업의 대화가 새 질문마다 따라붙는다는 걸
알고 나서야 이유를 알았죠.
이 부분에서 막히는 분이 꽤 많더라고요.

아래 기준대로 나눠 쓰시면 됩니다.

상황쓰는 명령하는 일
새 작업을 시작할 때/clear이전 대화를 비움
같은 작업을 이어 갈 때/compact대화를 요약해 줄임

/compact 뒤에 남기고 싶은 내용을 적어 줄 수도 있습니다.
공식 문서의 예시는 테스트 결과와 코드 변경에 집중하라는 뜻입니다.

/compact Focus on test output and code changes
【사진 03】
📌 전문가 Tip: /clear는 되돌릴 수 없습니다.
나중에 다시 볼 대화라면 먼저 /rename으로 이름을 붙이고,
비운 뒤에 /resume으로 돌아오면 됩니다.

Step 2. 모델은 어떻게 고를까?

기본이 끝났다면 이제 모델을 살펴볼 차례입니다.
모델은 클로드의 종류인데요, 큰 모델일수록 어려운 일을 잘하지만
한 번 쓸 때 한도를 더 많이 씁니다.
공식 도움말은 Sonnet이 코딩 작업 대부분에 알맞다고 안내합니다.
Opus는 Sonnet보다 한 번에 몇 배 더 들기 때문에
쉬운 일에는 아끼는 편이 좋습니다.

쉬운 작업인데도 가장 큰 모델을 그대로 두고 쓰다가
한도가 빨리 닳았다는 이야기를 자주 보게 되더라고요.
저도 그 뒤로는 쓰던 모델부터 확인하는 습관이 생겼어요.

【사진 04】
모델어울리는 일한도 부담
Haiku이름 바꾸기 같은 단순 작업가장 적음
Sonnet기능 개발, 테스트, 리팩터링중간
Opus어려운 디버깅, 큰 설계 판단가장 큼

/model을 입력하면 대화 중에도 모델을 바꿀 수 있고,
바꿔도 대화 내용은 사라지지 않습니다.
계획은 Opus로, 실행은 Sonnet으로 나누고 싶다면
아래 명령 하나면 됩니다.

/model opusplan

Step 3. 파일은 어떻게 알려 줘야 할까?

붙여 넣은 내용은 그 대화가 끝날 때까지 통째로 남습니다.
파일 경로로 알려 주면 클로드가 필요한 부분만 골라 읽습니다.
다만 경로 앞에 @를 붙이면 파일 전체가 들어가니
아끼고 싶을 때는 @ 없이 경로만 적으세요.

요청도 구체적일수록 좋습니다.
"이 코드를 개선해줘"처럼 막연하게 말하면
클로드가 더 많은 파일을 뒤지게 되기 때문입니다.
오류 로그는 관련된 20~30줄만 추려서 붙여 넣으세요.

src/auth.ts의 validateToken 함수에서 만료 시간 처리만 확인해줘
【사진 05】

Step 4. CLAUDE.md는 얼마나 줄여야 할까?

CLAUDE.md는 매 대화 앞에 붙는 파일입니다.
캐시 덕분에 두 번째 질문부터는 비용이 훨씬 싸지만,
그래도 대화창의 자리는 계속 차지합니다.
공식 도움말은 200줄 이하로 간결하게 두라고 안내합니다.

처음엔 메모를 하나둘 붙이다가
어느새 파일이 길어져 있는 경우가 많더라고요.
저도 몇 주에 한 번은 읽어 보면서
지금은 맞지 않는 내용을 지우는 편이 낫다고 느꼈어요.

• 같은 지적을 두 번 했을 때만 새로 적기
• 특정 작업 전용 지침은 스킬로 옮기기
• 맞지 않게 된 낡은 내용은 지우기

스킬은 필요할 때만 불러오는 지침 묶음이라
평소 대화의 짐이 줄어듭니다.

【사진 06】

Step 5. 어디서 새는지는 어떻게 확인할까?

마지막으로 새는 곳을 눈으로 확인하는 단계입니다.
/usage를 입력하면 이번 대화의 토큰 사용량이 나옵니다.
구독 요금제라면 무엇이 한도를 많이 썼는지와
줄이는 방법도 함께 보여 줍니다.

/context는 지금 대화창에 무엇이 들어 있는지 보여 줍니다.
안 쓰는 연결 서버(MCP)가 보인다면
/mcp에서 꺼 두세요.

📌 전문가 Tip: 습관 하나를 바꾸고 /usage로 비교해 보세요.
어떤 습관이 내게 맞는지 숫자로 알 수 있습니다.
