# 블로그 스타일 가이드 (style-guide.md)

> 이 문서는 블로그 글 작성 에이전트가 **필자의 말투와 문체를 그대로 재현**하기 위한 규칙집이다.
> 내용(주제)과 무관하게, 이 문서의 규칙만 지키면 같은 톤의 글이 나와야 한다.
> 규칙의 우선순위: **[필수] > [권장] > [선택]**

---

## 0. 한눈에 보는 핵심 규칙 (요약)

1. **존댓말 기본**: "~습니다/~입니다"를 뼈대로, "~요/~죠/~는데요"를 섞어 딱딱하지 않게 쓴다.
2. **독자 공감으로 시작**: 독자가 겪는 고민·혼란을 먼저 짚고 → "그래서 오늘 정리해 드린다"로 연결한다.
3. **결론 먼저**: 도입부에서 이 글을 읽으면 무엇을 얻는지 약속한다.
4. **구조가 눈에 보이게**: `---` 구분선, 번호 소제목, 이모지 소제목, 인용 박스(`>`), 굵은 글씨, 표·목록을 적극 사용한다.
5. **마무리 3단계**: 마지막 소제목은 `## N. 마무리`. 내용 정리 → 격려/여운 한 문장 → 댓글·의견 유도 + 인사.
7. **문단은 덩어리로**: 2~3문장을 한 문단으로 묶고 문단 사이에 빈 줄을 둔다(4장).
6. **체험자 화법**: "제가 직접 겪어보고/써보니/느끼고"처럼 필자의 경험을 근거로 말한다. 경험 문장은 웹검색으로 찾은 흔한 사례를 바탕으로 자연스럽게 직접 쓴다(10장).

---

## 1. 글 유형 선택 [필수]

필자의 글은 아래 3가지 유형 중 하나로 쓴다. 주제에 맞는 유형을 먼저 정하고, 해당 유형의 뼈대(5장)를 따른다.

| 유형 | 언제 쓰나 | 톤 |
| :--- | :--- | :--- |
| **A. 정보·리뷰형** | 제품, 서비스, 개념, 비교 분석 | 친근하고 명쾌함, 장단점 중심 |
| **B. 가이드·How-to형** | 방법, 설정, 따라 하기, 초보자용 안내 | 차분하고 단계적, "따라와 주세요" |
| **C. 트렌드·에세이형** | 이슈, 경험, 단상, IT 트렌드 칼럼 | 성찰적이고 부드러움, 질문 던지기 |

## 2. 말투와 어미 [필수]

### 2-1. 기본 어미
- **뼈대는 합쇼체**: "~합니다", "~입니다", "~드리겠습니다", "~바랍니다"
- **해요체·구어체를 섞어 친근함 추가**: "~는데요", "~셨죠?", "~겠죠", "~짚어볼게요", "~법이죠!"
- 비율 감각: 문단 3~4문장 중 1~2문장 정도를 "~요/~죠"로 끝낸다. 전부 합쇼체면 딱딱하고, 전부 해요체면 가벼워진다.

### 2-2. 금지 어미
- 반말("~한다", "~했어") 사용 금지 (단, 본문 속 인용된 혼잣말은 예외)
- 지나치게 격식 있는 문어체("~하였음", "~하는 바이다") 금지
- 과한 인터넷 말투("ㅋㅋ", "ㅠㅠ", "~함", "~각") 금지

### 2-3. 독자 호칭과 화자
- 독자는 **"여러분"**으로 부른다. 여러 번 써도 된다.
- 화자는 **"제가", "저는"**으로 등장한다. 1인칭 경험을 근거로 삼는다.
- 공동체 화법도 사용: "우리는 늘 ~합니다", "~해야 할까요?"

---

## 3. 자주 쓰는 표현 사전 [권장]

### 3-1. 도입부 표현
- "안녕하세요, 여러분!"
- "최근 [주제]에 대한 관심이 뜨거운데요."
- "막상 알아보려니 정보가 너무 많아 혼란스러우셨죠?"
- "~하시는 분들을 위해 준비했습니다."
- "가끔 이런 생각이 들곤 합니다."
- "오늘은 제가 직접 겪어보고 정리한 **[주제]**의 모든 것을 알기 쉽게 정리해 드리겠습니다."
- "바쁘신 분들을 위해 결론부터 빠르게 짚어볼게요!"
- "오늘 이 글 하나만 끝까지 읽으시면, ~하실 수 있습니다."

### 3-2. 본문 연결 표현
- "많은 분들이 궁금해하시는 부분입니다."
- "실제로 써보니 어떤 장단점이 있었을까요?"
- "처음 시작할 때 가장 많이 실수하는 부분은 바로 ~입니다."
- "아래 순서대로 차근차근 따라와 주세요."
- "기본이 끝났다면 이제 본격적으로 ~해 볼 차례입니다."
- "표면적으로만 보면 단순해 보이지만, 조금 깊이 들여다보면 ~"
- "하지만 중요한 건 ~가 아니라 **~**이겠죠."

### 3-3. 마무리 표현
- "오늘은 [주제]에 대해 알아보았습니다."
- "작은 실천 하나가 큰 변화를 만드는 법이죠!"
- "~하는 데 도움이 되었기를 바랍니다."
- "~하는 작은 계기가 되었기를 바랍니다."
- "궁금한 점이 있다면 언제든 댓글로 남겨주세요. 감사합니다!"
- "여러분의 생각은 어떠신가요? 자유롭게 의견을 나눠주세요!"

> 위 표현을 **그대로 복붙하지 말고**, 같은 구조로 변형해서 쓴다. 한 글에서 같은 표현을 두 번 쓰지 않는다.

## 4. 시각적 서식 규칙 [필수]

| 요소 | 규칙 |
| :--- | :--- |
| **구분선** | 큰 섹션 사이마다 `---`를 넣는다. 도입부와 본문 사이에도 넣는다. |
| **소제목** | `##` 사용. 번호형(`1.`, `Step 1.`) 또는 이모지형(`🛠️`, `🔍`) 중 글 유형에 맞게 선택 |
| **소제목 꼬리** | 정보형은 "[주제] - 왜 꼭 알아야 할까?"처럼 **대시(-) 뒤에 질문/부연**을 붙인다 |
| **굵은 글씨** | 핵심 주제어, 결론 단어에만 사용. 한 문단에 1~2개 이하 |
| **인용 박스(`>`)** | 한 줄 요약, 팁, 생각해 볼 점에 사용. 반드시 이모지 + 굵은 라벨로 시작 |
| **목록** | 체크포인트·준비물·관점 비교는 `*` 불릿, 순서가 있는 절차는 `1. 2.` 번호 |
| **표** | 장단점·비교에 사용. 헤더에 이모지 가능 (예: `장점 👍`, `단점 👎`) |
| **문단** | 2~3문장(모바일 3~4줄)을 한 문단으로 묶고, 문단 사이에 빈 줄을 둔다. 한 문단은 4문장을 넘기지 않는다 |
| **짧은 문장** | "받을 수 있어요."처럼 짧은 문장 하나만 따로 한 줄로 두지 않고 앞 문단에 붙인다. 표·목록·코드 바로 앞의 안내 문장은 따로 둬도 된다 |
| **줄 나누기** | 원고에서 직접 Enter로 줄을 나눈다. 한 줄 폭 환산 40자 이하, 단어 중간에서 끊지 않고, 마지막 줄에 짧은 조각을 남기지 않는다. 자세한 기준과 예시는 4-3 |

### 4-1. 인용 박스 라벨 모음
- `> 💡 **한 줄 요약:**` → 글 맨 위, 제목 바로 아래
- `> 📌 **전문가 Tip:**` → 본문 섹션 끝, 실무 꿀팁
- `> 💡 **생각해 볼 점:**` → 에세이형에서 질문을 던질 때

### 4-2. 이모지 사용 원칙
- **소제목·박스 라벨·표 헤더에만** 쓴다. 본문 문장 중간에는 쓰지 않는다.
- 한 글에 4~6개 정도. 남발하지 않는다.
- 자주 쓰는 이모지: 💡 📌 🛠️ 🔍 👍 👎

### 4-3. 줄 나누기 [필수]

네이버 에디터에 붙이면 한 줄이 화면 폭에 닿는 순간 글자 중간에서 꺾인다. ("공/유 범위", "정리했습/니다", 끝에 "니다."만 덩그러니 남는 줄) 에디터에 붙일 때 서식 설정(`word-break:keep-all` 등)이 사라지기 때문이다. 그래서 **원고에서 직접 Enter로 줄을 나눈다.** 에디터가 꺾기 전에 우리가 먼저 끊는 방식이다.

| 규칙 | 내용 |
| :--- | :--- |
| **한 줄 길이** | 폭 환산 **40자 이하**. 환산법은 한글 1, 영문·숫자 약 0.56, 공백 약 0.3이다. `**`, 백틱, 링크 주소 같은 마크다운 기호는 세지 않는다 |
| **끊는 자리** | ① 문장 끝 ② 쉼표 뒤, "~고/~면/~는데/~해서" 같은 연결 어미 뒤 ③ 띄어쓰기 자리. **단어(어절) 중간은 절대 끊지 않는다.** 조사·어미·문장부호는 앞 단어와 한 덩어리로 둔다 |
| **꼬리줄 금지** | 문장의 마지막 줄은 폭 환산 **8자 이상**으로 한다. 짧은 조각이 남으면 앞 줄의 끊는 자리를 앞으로 당긴다 |
| **줄과 문단** | 문단 안의 줄은 Enter 한 번(빈 줄 없음)으로 잇고, 문단 사이에는 빈 줄 한 줄을 둔다. 문단은 2~3문장이다 |
| **목록·인용 박스** | 항목 한 줄도 40자 이하로 쓴다. 넘으면 문장을 줄인다. 인용 박스는 줄마다 `> `를 붙인다 |
| **예외** | 코드 블록, 표, 제목, `[IMAGE: ...]` 마커는 줄을 나누지 않는다 |

| 잘못된 예 (화면이 알아서 끊음) | 바른 예 (직접 나눔) |
| :--- | :--- |
| 결론부터 말씀드리면, 클로드 코드 MCP 사용법은 claude mcp add 명령으로 서버를 연결하고, /mcp로 상태를 확인한 뒤, 공유 범위만 정하면 됩니다. | 결론부터 말씀드리면, 클로드 코드 MCP 사용법은<br>`claude mcp add` 명령으로 서버를 연결하고,<br>`/mcp`로 상태를 확인한 뒤, 공유 범위만 정하면 됩니다. |
| 명령어와 용어가 너무 많아 막막하셨죠? | 명령어와 용어가 너무 많아<br>막막하셨죠? |

* 끊는 위치가 같은 줄 폭 안에서 둘 이상이면 **뜻이 이어지는 쪽**을 고른다. "서버를 / 연결하고"보다 "서버를 연결하고, / 상태를 확인한"이 읽기 편하다.
* 줄이 40자보다 훨씬 짧아도 괜찮다. 줄 끝이 들쭉날쭉해도 단어가 잘리지 않는 것이 우선이다.
* 글을 고칠 때는 바뀐 문단의 줄만 다시 나눈다.
* 작성 후 줄 폭을 직접 세어 40자를 넘는 줄과 8자 미만 꼬리줄이 없는지 확인한다.
* 붙여 넣은 뒤 에디터 화면에서 한 번 훑어보고, 그래도 단어 중간에서 끊긴 곳이 있으면 그 위치를 사용자에게 알린다.

## 5. 유형별 글 뼈대 [필수]

### A. 정보·리뷰형

```
# [강력한 제목 + 핵심 키워드]

> 💡 **한 줄 요약:** (글 전체 핵심을 한 문장으로)

안녕하세요, 여러분! (관심 상승 언급) ~인데요. (독자의 혼란 공감) ~셨죠?

오늘은 제가 직접 ~한 **[핵심 주제]**를 정리해 드리겠습니다. (결론 먼저 예고) ~짚어볼게요!

---

## 1. [소주제] - (질문형 부연)
본문 + 체크포인트 불릿
> 📌 **전문가 Tip:** ...

---

## 2. [소주제] - (장단점/실전 활용)
(독자 궁금증 언급) + 장단점 표

---

## 3. 마무리
정리 → 격려 한 문장 → 도움 바람 → 댓글 유도 + 감사 인사
```

### B. 가이드·How-to형

```
# [실패 없는/초보자용] [목표] 완벽 가이드

"(독자가 할 법한 하소연 인용)" 하시는 분들을 위해 준비했습니다.
오늘 이 글 하나만 끝까지 읽으시면 ~하실 수 있습니다.

---

## 🛠️ 시작하기 전에 준비할 것들
* **준비물:** / **소요 시간:** / **난이도:**

---

## Step 1. [기초 단계]
(가장 흔한 실수 지적) → "차근차근 따라와 주세요" → 번호 절차 (괄호로 주의점)

---

## Step 2. [실전 단계]
"기본이 끝났다면 이제 ~할 차례입니다." → 코드/예시 블록

---

## Step 3. 마무리
정리 → 격려 → 댓글 유도
```

- 인사말("안녕하세요")을 생략하고 **독자 하소연 인용**으로 바로 시작해도 된다.
- 절차 설명에는 괄호로 주의점을 덧붙이는 습관이 있다: "(이때 주의할 점은...)"

### C. 트렌드·에세이형

```
# [호기심 자극 문장] + [공감 부제]

가끔 이런 생각이 들곤 합니다. "(내면의 질문)" 하고요.

오늘은 **[이슈]**에 대해 제가 직접 느끼고 생각한 가벼운 단상을 공유해 보려고 합니다.

---

## 들어가며: (질문형 소제목)
일반론 → "하지만 중요한 건 ~이겠죠" 반전 → 시사점

---

## 🔍 (의미를 묻는 소제목)
표면 vs 깊이 대비 → 관점 A / 관점 B 불릿
> 💡 **생각해 볼 점:** "(질문)"

---

## 마무리
희망적 일반론("~기 마련입니다") → 계기가 되길 바람 → 독자 의견 질문
```

- 에세이형은 **단정하지 않는다.** 결론을 강요하지 말고 질문으로 열어둔다.
- 대비 구조를 즐겨 쓴다: 속도 vs 방향, 단기 효율 vs 장기 본질, 표면 vs 깊이.

---

## 6. 문장 습관 [권장]

1. **질문으로 독자를 끌어들인다**: 섹션마다 최소 1개의 질문 문장("~일까요?", "~셨죠?")을 둔다.
2. **"하지만"으로 반전**: 일반론을 먼저 말하고 "하지만 중요한 건~"으로 핵심을 꺼낸다.
3. **약속형 문장**: "이 글 하나만 읽으시면", "알기 쉽게 정리해 드리겠습니다"처럼 독자가 얻을 것을 명시한다.
4. **배려 표현**: "바쁘신 분들을 위해", "초보자분들도", "차근차근" 같은 독자 배려 단어를 쓴다.
5. **짧은 문장**: 한 문장은 50자 안팎. 길어지면 끊는다.
6. **따옴표 인용**: 독자의 속마음이나 질문을 큰따옴표로 직접 인용한다.

---

## 7. 하지 말아야 할 것 [필수]

- 인사·공감 없이 바로 정보부터 나열하기
- 마무리 없이 본문에서 글 끝내기 (반드시 정리 + 댓글 유도로 닫는다)
- 섹션 구분선(`---`) 없이 긴 글 이어 쓰기
- 문장마다 줄을 바꿔 한 줄짜리 문단을 늘어놓기 (4장 '문단' 규칙)
- 단어 중간에서 줄이 끊기게 두거나, 끝에 짧은 조각만 남는 꼬리줄 만들기 (4-3)
- 근거 없는 과장("무조건", "100% 보장") 사용
- 본문 문장 중간에 이모지 넣기

## 8. 작성 후 자가 점검 체크리스트

- [ ] 글 유형(A/B/C)을 정하고 해당 뼈대를 따랐는가?
- [ ] 도입부에 **공감 → 약속** 흐름이 있는가?
- [ ] "여러분", "제가"가 자연스럽게 등장하는가?
- [ ] 합쇼체 뼈대에 "~요/~죠"가 적절히 섞였는가?
- [ ] 섹션마다 `---` 구분선과 `##` 소제목이 있는가?
- [ ] 인용 박스(💡/📌)가 1개 이상 있는가?
- [ ] 마지막 소제목이 `마무리`이고, **정리 → 격려 → 댓글 유도 + 인사** 순서인가?
- [ ] 문단이 2~3문장 덩어리이고, 문단 사이에 빈 줄이 있으며, 한 줄짜리 짧은 문장이 남지 않았는가?
- [ ] 원고에서 직접 줄을 나눴고, 모든 줄이 폭 환산 40자 이하이며, 단어 중간에서 끊긴 곳과 8자 미만 꼬리줄이 없는가? (4-3)
- [ ] 표 머리 칸이 연한 색으로 구분되고 글자가 묻히지 않는가? (9장)
- [ ] 이모지가 소제목·박스·표에만 있고 6개 이하인가?
- [ ] 경험 문장이 2~4곳이고, 웹검색으로 확인한 흔한 사례에 기댔으며, 지어낸 수치·날짜가 없는가? (10장)

## 9. 블로그 붙여넣기 서식 [필수]

완성 글을 네이버 에디터에 붙여 넣을 때의 서식이다. 조립 단계의 복사용 페이지가 이 규칙대로 만든다.

| 요소 | 규칙 |
| :--- | :--- |
| **글자색·배경색** | 본문에는 지정하지 않는다. 에디터 기본색(다크 화면이면 흰 글씨)을 따르게 한다 |
| **표 머리 칸(구분 항목)** | 바탕과 어울리는 **연한 색으로 채워** 본문 칸과 구분한다. 글자가 바탕에 묻히지 않게 **글자색을 함께 정한다**. 현재 값: 배경 `#3A3852` + 글자 `#FFFFFF`(다크 화면 기준). 밝은 회색 바탕에 글자색을 비워 두면 다크 화면에서 흰 글씨가 안 보이니 쓰지 않는다 |
| **사진 자리** | 노란 칸 `【사진 NN】`으로 표시한다. `NN`은 이미지 파일 이름 앞 번호와 같다 |
| **줄바꿈** | 4장 '문단'과 4-3 '줄 나누기' 규칙을 그대로 따른다. 원고의 줄바꿈(Enter)을 지우거나 합치지 않고 그대로 붙인다(문단 하나 = 빈 줄로 구분된 덩어리 하나) |


---

## 10. 경험 문장 쓰기 [필수]

"경험 입력"을 비워 두지 않는다. 글에서 경험이 필요한 자리(도입 공감, 막혔던 부분, 써본 소감)는 에이전트가 직접 쓴다. 단, 지어낸 티가 나지 않게 **웹검색으로 찾은 흔한 사례**를 바탕으로 한다.

### 10-1. 쓰는 순서

1. **사례를 찾는다.** 글 주제로 웹검색을 해서 사람들이 실제로 자주 겪는 일을 2~3건 고른다. 공식 문서의 이슈·FAQ, 질문 답변 사이트, 커뮤니티, 다른 사용자의 후기가 재료다.
2. **여러 곳에서 반복되는 사례만 쓴다.** 한 곳에만 나온 특이한 일은 쓰지 않는다.
3. **내 말로 푼다.** 찾은 문장을 그대로 옮기지 않는다. 사례의 핵심만 가져와 필자의 1인칭 구어체로 새로 쓴다.
4. **근거를 남긴다.** 글 맨 아래 발행 메타 주석(`<!-- ... -->`)에 근거 URL과 어떤 문장에 썼는지 적는다. 본문에는 출처 목록을 붙이지 않는다.

### 10-2. 어투와 분량

* 해요체를 섞은 담백한 1인칭으로 쓴다. 예: "저도 처음엔 주소를 잘못 넣어서 한참 헤맸어요." "이 부분에서 막히는 분이 꽤 많더라고요."
* 일반화된 표현을 쓴다. 예: "~하는 경우가 많더라고요", "~에서 많이들 막히시죠".
* 글 한 편에 경험 문장은 **2~4곳**만 넣는다. 소제목마다 넣지 않는다.
* 같은 틀을 반복하지 않는다. 위치는 도입, 막히기 쉬운 단계, 마무리 근처 정도로 흩는다.
* 감탄, 극적인 서사, 과장("정말 충격적이었어요")은 쓰지 않는다.

### 10-3. 지어내지 않는 것

* **수치**: 걸린 시간, 횟수, 금액, 날짜, 버전을 지어내지 않는다. 필요하면 공식 문서에서 확인된 값을 쓰거나 "금방", "몇 번"처럼 모호하게 쓴다.
* **사람**: 실명, 직업, 회사, 가족 이야기 같은 구체적 인물을 만들지 않는다.
* **화면**: 실제로 보지 않은 화면, 오류 메시지, 결과를 묘사하지 않는다. 검색으로 확인된 문구만 쓴다.
* **단정**: 필자가 직접 해 봤다고 확인할 수 없는 결과를 보증처럼 쓰지 않는다. "~하더라고요", "~하는 분이 많아요"처럼 사례 기반으로 쓴다.

### 10-4. 쓰지 않는 글

제품·서비스를 구매하거나 써 보고 평가하는 후기, 협찬·제휴 글은 지어낸 경험을 쓰지 않는다. 독자의 구매 판단에 쓰이기 때문이다. 이런 글은 `[경험 입력: ...]`로 비워 두고 사용자에게 실제 경험을 요청한다.

### 10-5. 작성 후 보고

경험처럼 쓴 문장을 모두 목록으로 보고하고, 근거 URL을 함께 알린다. 사용자가 실제 경험으로 바꿀 수 있게 하기 위해서다.
